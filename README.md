# midway-docs

Public documentation for the Midway protocol. This repository is synced to a
GitBook space through GitBook's Git Sync integration.

## How pages are generated

Most pages under `docs/` are written by hand. A few reference pages
(`docs/reference/deployments.md`, `docs/reference/launch-configuration.md`,
and every file under `docs/reference/contracts/`) are generated by
`scripts/render.mjs` from the JSON files in `data/`. Those pages carry a
`do not edit` comment under the title. Edit the data file or the render
script instead, then run:

```bash
npm run render
```

## Build

This same tree serves two outputs from the same markdown: GitBook Git Sync (reads
`.gitbook.yaml`, `docs/README.md`, `docs/SUMMARY.md` directly) and a static site built with
[VitePress](https://vitepress.dev) and deployed on Netlify (`netlify.toml`, config in
`docs/.vitepress/`). Neither one requires changes to the page layout; the VitePress config
derives its sidebar from `docs/SUMMARY.md` and maps GitBook's `README.md` convention onto
VitePress's `index.md` routing.

```bash
npm ci
npm run build
```

Output goes to `docs/.vitepress/dist`. `npm run docs:dev` runs a local dev server; `npm run
preview` serves the built output.

## Contributing

1. Edit files under `docs/`. Follow the existing page structure and keep
   `docs/SUMMARY.md` in sync with any pages you add or remove.
2. Run the checks before opening a pull request:

   ```bash
   npm run check
   ```

3. Open a pull request. CI runs the same check on every push and PR.

Style: plain, short sentences. No em dashes or en dashes. No marketing
language. No addresses in prose, contract addresses live only in
`data/*.json` and the generated reference pages.
